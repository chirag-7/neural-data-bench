# B03 processed-raster rigid-motion diagnostic

This is an explicitly synthetic simulation endpoint with known imposed displacement, not in-vivo probe motion validation or full spike sorting. It is prepared before any general model calls or real-slice reference scores. Parent review and a separate freeze are required. It uses the official SpikeInterface0.105.4 `generate_drifting_recording` machinery; generator and registration source are preserved with MIT licenses. No external biological dataset is copied or algorithm output used as gold.

Eight complete independent simulations each cover90seconds with64neurons recorded on64contacts: two32-contact columns,32um horizontal pitch,20um vertical pitch, depth0–620um;20kHz sampling. All eight are retained. Four simulations train and four are held out, with distinct simulator seeds generating different neuron positions, ellipsoid waveform parameters, Poisson spike trains and noise realizations. Every train/test split includes two triangular and two random-walk motion profiles, balanced across two noise regimes. Simulator seeds and per-test motion trajectories/periods are evaluator-only metadata and must not be disclosed to submitted programs or used to regenerate targets. Reproducibility parameters and array hashes are retained in the data manifest and acquisition code, outside the generation prompt.

The official procedural generator uses spatially decaying heterogeneous ellipsoid waveforms (alpha100–500, decay10–45um),2–8Hz firing with4ms refractory period,15% per-spike amplitude variation, and spatially correlated nonzero Gaussian noise (25um decay, per-channel standard deviations sampled in6–10or10–14uV). Motion is rigid axial displacement within±30um with5Hz state updates and2um template-position grid. This includes spike collisions, signal loss at probe boundaries, low-amplitude units, noisy detection and localization bias. It is not a noiseless translated image. These are simplified synthetic waveform/noise families, not biophysical MEArec cells or biological population replication. No MEArec simulation license is asserted because no MEArec data is used.

Shared preparation: bandpass the generated voltage300–6000Hz with a third-order filter; estimate channel noise by MAD on20fixed randomly sampled0.2s voltage chunks; detect negative locally-exclusive peaks at5noise-SD within50um/1ms neighborhoods; center-of-mass localize using PTP waveforms within60um over±0.5ms. This standard fixed front end is identical for all contestants and never receives true unit IDs, positions, spike events or displacement. Preserve detected peak arrays and locations for independent reconstruction. All90seconds are included, without activity or performance-based window selection. Voltage is generated lazily during preparation; retained seeds/configuration plus first-second filtered-voltage checksum support regeneration. The full waveform movie is not passed to submissions.

`train_x` and `test_x` each have shape `(4,90,132)`: one complete recording per row,90one-second bins by132depth bins of5um spanning[-20,640]um. Values are raw detected-peak counts, not true spike counts or true unit locations. There is no smoothing, clipping, per-raster normalization, stimulus covariate or source ID predictor. Use `fit_predict(train_x,train_y,test_x,train_groups)` with `train_groups=None`; each training row is an independent simulation. Train-only validation may hold out entire simulation rows; do not split correlated time bins at random. Each test recording may be processed independently with offline/acausal temporal context. Do not join rows or borrow information across independent test simulations.

Training targets have shape `(4,90)`, in micrometers. They come directly from the generator's hidden physical displacement states, quantized to the actual nearest2um template grid used by the injector, then averaged over the five200ms states within each1s bin. All neurons share this rigid displacement. Remove each recording's temporal mean to define relative displacement. This mean bin displacement is a custom target; the original SI benchmark's interpolation at bin centers is not substituted. A positive displacement means tissue/spike depth moves toward increasing probe y. No unit identity or true source position is an input feature.

Return finite displacement array `(len(test_x),90)` in micrometers, with arbitrary constant offset permitted per recording. Scorer subtracts the temporal mean independently from predictions and truth, computes RMSE over all90timebins per heldout recording, and averages the four recording RMSEs equally. Lower is better. Per-recording MAE and maximum absolute error are secondary. Scorer never selects a sign, temporal shift, scale or best-fitting trajectory; only the unidentifiable constant translation gauge is removed. All four heldout simulations must produce finite predictions; no source or time-bin exclusion. Seed-level variation is descriptive Monte Carlo replication within one simulator, not independent animals.

Fixed specialist reference: unchanged SpikeInterface0.105.4 decentralized-registration numerical routines `compute_pairwise_displacement` and `compute_global_displacement` applied directly to the same supplied count rasters. Use5um spatial bins, normalized centered NumPy cross-correlations, maximum pairwise displacement60um, correlation threshold0.1, linear correlation values, all time-bin pairs, and LSMR with temporal prior, without spatial prior. The global solver uses its default hard edge selection (`soft_weights=False`): correlations above threshold identify usable edges rather than continuously weighting their least-squares residuals. Subtract the resulting mean per recording. No template, true spike, true displacement, training-target fitting or test-target tuning is supplied to this reference. This is official SI specialist numerical code on a custom front end/geometry, not a complete DREDge wrapper reproduction or a current-best claim. Unequal development and training effort prevents a causal general-versus-specialist superiority claim.

Eventual general generation: exact gpt-5.6-sol/gpt-6-sol/gpt-6.1-sol, high effort, one no-tool generation, fewer than240lines,180seconds for the full fit/predict call, one numerical CPU thread. General NumPy/SciPy/sklearn only; no specialized motion packages, simulator imports, file/network access, pretrained assets, source lookup or target regeneration. No changes after scoring feedback. Freeze prompt, package source, adapter, input and target hashes before dispatch.
