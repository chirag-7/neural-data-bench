# L06: posterior sampling for a spiking-neuron GLM

This is a custom likelihood-informed code-generation track on all ten original **sbibm Bernoulli GLM** observations. It evaluates whether a general model can construct a numerical posterior sampler. It is **not the original simulator-only SBI leaderboard**, and does not test native neural signal perception.

## Original source and preparation

Author repository [sbibm](https://github.com/sbi-benchmark/sbibm), commit `f0bc44039e6b7e095c18d4e9e64819d75be76587`; [benchmark paper](https://proceedings.mlr.press/v130/lueckmann21a.html). All ten observation IDs are included without outcome selection. Original design tensor, raw spikes, sufficient statistics and 10,000 reference posterior draws per observation are acquired directly and hashed in [the manifest](../../data/manifests/L06.json). No true-parameter file is acquired or supplied. Original source and MIT notice are retained in `upstream/`. Repository software terms are not asserted to license unrelated biological data; these numerical simulations are supplied by the original benchmark repository. Source and prepared numerical arrays stay in the ignored cache; committed predictions are our numerical simulation outputs.

The fixed design has 100 rows and ten columns: intercept plus nine causal stimulus lags. Original float32 tensor storage is read without executing pickle objects, and every value is checked against the author's NumPy seed-42 construction. The prior precision is reproduced from the author's float32 smoothness construction. All raw binary observations are checked against published sufficient statistics. Computation subsequently uses float64. Ten observations share a design and simulator; they are not independent biological recordings.

## Model interface and likelihood

`sample_posterior(design_matrix, spike_trains, prior_precision, n_samples, seed)` returns a finite array `(10, 10000, 10)` of posterior parameter draws. The model receives all ten observed spike sequences and a known, common likelihood:

`log posterior(beta) = sum(y * (X @ beta) - logaddexp(0, X @ beta)) - beta.T @ Q @ beta / 2 + constant`.

Each observation has its own posterior. Observations may share computation but may not be pooled as if generated by one parameter vector. Prior mean is zero; intercept is parameter zero. Prior precision is positive definite. Reference posterior samples, true parameters and scorer outputs are absent from generation and sampler arguments. Inputs are observations, not training/test labels. There is no supervised training split and no claim of unseen-model-family transfer.

One generation per requested model, high reasoning effort, identical explicit prompt, no tools or execution feedback. Generated code may import only NumPy, SciPy, scikit-learn and standard utility modules already allowed in this project. No specialist packages, pretrained assets, file/network access or dynamic execution. Under 240 lines, deterministic seed `20261031`; **180 seconds total for all ten posteriors**, one numerical CPU thread. Approximately 4 GB memory requested, not enforced. No repair or extra generation after test feedback. Scoring time is outside sampler time, equally for every method.

## Frozen reference methods

- **Local Polya–Gamma Gibbs sampler**: adaptation of the original author reference algorithm, using `polyagamma==2.0.2` instead of `pypolyagamma`. Initialize at a likelihood/prior MAP found from the observed spikes, never the hidden true parameters. Per observation: 2,500 warmup sweeps, keep every second draw for 10,000 samples. These settings are fixed before any method is scored. Original archived reference used 25,000 warmup and thinning 25, and initialized at truth; our shorter local chain is not an exact reproduction or guaranteed convergence certificate. The original PG reference and the local PG comparator are algorithmically related; this favors a family-specific reference and is disclosed.
- **Laplace approximation**: MAP and inverse Hessian Gaussian, fixed deterministic optimization and 10,000 random draws. Conventional approximation, not a certified best specialist.

Both receive exactly the same numerical observations/prior as generated programs. The PG package is available only to the specialist. Its implementation language/effort differs from generated samplers. No global best, equal total research effort or original SBI simulation-budget comparison is claimed. Runtime preflight uses fresh synthetic data only.

## Scoring fixed before generation

Primary: arithmetic mean over all ten observations of **classifier two-sample-test accuracy**, lower and nearer 0.5 is better. We adapt the original [sbibm C2ST implementation](https://github.com/sbi-benchmark/sbibm/blob/f0bc44039e6b7e095c18d4e9e64819d75be76587/sbibm/metrics/c2st.py): take draws `0,5,...,9995` (2,000) from each generated and reference posterior; normalize both using the reference subset's coordinate mean/sample SD; fit five shuffled KFold classifiers, seed 1. MLP: two 100-unit ReLU layers, Adam, max_iter 10,000; other scikit-learn 1.9.1 defaults. Both normalized matrices are float32 and the mean fold accuracy is cast float32 as upstream. This **2,000-draw metric is a CPU-sized custom evaluation, not the original 10,000-draw leaderboard number**. No clipping at 0.5; finite-sample scores near/below chance do not establish superiority. Classifier performance is a diagnostic, not a formal proof of posterior equality. Store held-out predictions/labels/fold indices for exact accuracy auditing. No score feedback is supplied to any method.

Secondary: 128-direction sliced Wasserstein-2 between all 10,000 draws and original reference, in prior-whitened parameter coordinates, with fixed directions from seed 1729; mean across observations. Also store per-observation parameter means/SDs, lag-one autocorrelation and split-chain diagnostics as descriptive checks, not proof of convergence. No confidence intervals treating draws or shared-design observations as independent biological units.

The first-submission aggregate may include this synthetic task only when synthetic tasks are enabled. It is excluded from the default biological-data generation trend. Original and newly added results remain separate, auditable records. A PG-reference chance-level score cannot establish the strongest possible performance.
